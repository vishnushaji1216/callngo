API Reference
Programmatic access to the Edesy number masking platform. Base URL: https://voice-api.edesy.in/v1

Quick start
Make your first masked call in under a minute. Replace the API key with your own (create one on the API Keys page), then run this in your terminal:

cURL
Node.js
Python
PHP
Copy
curl -X POST https://voice-api.edesy.in/v1/masking/calls \
  -H "Authorization: Bearer vp_YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
        "party_a": "9876543210",
        "party_b": "9123456789"
      }'
That's it — we dial Party A, and when they answer we bridge Party B. Both parties see the masked number as caller ID. The response includes a call_sid you can use to poll status and fetch the recording.

Authentication
All API requests are authenticated with a Bearer token. Treat your API key like a password — store it in an environment variable, never commit it to source control.

Authentication
Every request must include an Authorization header with your API key:

Authorization: Bearer vp_your_api_key_here
Your key starts with vp_d1bd962b1... — the full key was shown only once when you created it. Manage keys on the API Keys page.

Your tenant ID (this workspace) — it appears as tenant_id on webhook events, call records, and request logs. You don't send it with requests; your key is already scoped to it.

Session API
Send two phone numbers, get back one temporary virtual number. Both parties use that same number to reach each other — we route each call to the opposite party based on who is calling, so neither ever sees the other's real number. Sessions expire automatically and hundreds can be active at once. A session is generic: use it for delivery, ride-hailing, marketplaces, classifieds — anything that needs two people to talk without sharing numbers.

Before you start

Buy a DID in the voice-app portal and enroll it into masking (Numbers → Add number). Enrolled numbers form the pool the session API allocates from — a virtual number is reused across many concurrent sessions as long as no participant appears on it twice, so a small pool covers a lot of sessions. Sized by peak concurrent sessions, not total.

Create a Session
POST
/masking/sessions
Binds two real numbers to one virtual number for a limited lifetime and returns the virtual number. Either party can then call that number and is bridged to the other — routing is decided by who is calling, so the same number works in both directions. Idempotent on `reference`: repeating the call for an active reference returns the existing session.

Body Parameters
Name	Type	Required	Description
party_a	string	Yes	First participant — 10-digit Indian mobile (with or without +91/91; we normalize).
party_b	string	Yes	Second participant. Either party may call the virtual number.
reference	string	No	Your external id for this session (order/ride/ticket id). Makes create idempotent and appears on events + CDRs.
expiry_minutes	integer	No	Auto-expire the session after this many minutes (1–43200). Omit for no expiry — end it explicitly instead.
max_calls	integer	No	Optional cap on the number of calls this session will route.
metadata	object	No	Arbitrary JSON stored with the session and echoed back on reads.

Event webhooks
Register one endpoint to be notified of session and call lifecycle events. We POST JSON as they happen, signed with HMAC-SHA256 so you can verify it came from us.

Event	Fires when
session.created	A session is created (a virtual number is bound to two parties).
call.incoming	A masked call arrives and is about to be bridged to the other party.
call.connected	The other party answered — the two are now talking.
call.ended	A connected call finished normally (includes duration_sec).
call.missed	A call failed, was busy, or went unanswered.
session.expired	A session ended — via End a Session or automatic TTL expiry.
Example delivery (headers + body):

POST https://api.yourapp.com/edesy/events
Content-Type: application/json
User-Agent: edesy-masking/1.0
X-Edesy-Signature: sha256=<HMAC-SHA256 of the raw body, keyed with your secret>

{
  "event": "call.ended",
  "reference": "ORD-4821",
  "virtual_number": "918071387146",
  "caller": "9876543210",
  "callee": "9123456789",
  "direction": "a_to_b",
  "call_sid": "d28be7cd-9840-4b23-9627-199f1ef81fc6",
  "duration_sec": 74,
  "status": "completed",
  "timestamp": "2026-07-14T18:12:40Z"
}

Call lifecycle
A call moves through these states from initiation to termination. Poll the call status endpoint until you see a terminal state.

initiated
ringing
answered
in-progress
completed
Plus terminal failure states: failed · no-answer

Status	Meaning
initiated	Call request accepted; dialing Party A.
ringing	Party A's phone is ringing.
answered	Party A picked up; bridging Party B.
in-progress	Both parties connected and talking.
completed	Call ended normally. Recording available shortly.
failed	Carrier or system error. See hangup_cause for details.
no-answer	Party A did not pick up within the ring timeout.
Poll GET /v1/masking/calls/:call_sid every 2–3 seconds. Stop polling once status is one of the three terminal values: completed, failed, or no-answer.

Number Masking Webhook
Bring your own routing: instead of storing pairings with us, point a masked number at your endpoint. For every inbound call we ask your webhook who to connect the caller to. Configure it per number under Numbers → Routing → Your webhook.

1. We POST to your URL
Method POST (or GET if you configured it), with these headers:

Content-Type: application/json
Accept: application/json
User-Agent: edesy-masking/1.0
X-Edesy-Signature: sha256=<HMAC-SHA256 of the raw body, keyed with your signing secret>
Body:

{
  "event": "masking.route",
  "call_sid": "b6f6e2a0-3c1d-4e8a-9f2b-2a1c9d4e5f60",
  "caller": "9547531359",
  "masked_number": "9484956709",
  "direction": "inbound",
  "timestamp": "2026-07-14T00:00:00Z"
}
A test event is identical but adds "test": true and an empty call_sid.

Request fields
Name	Type	Required	Description
event	string	Yes	Always "masking.route".
call_sid	string	Yes	Jambonz call ID. Empty string for test events.
caller	string	Yes	Who is calling — 10 digits, country code stripped.
masked_number	string	Yes	The masked DID that was dialed — 10 digits.
direction	string	Yes	"inbound".
test	boolean	No	Present and true only for test events (the “Send test event” button).
timestamp	string	Yes	RFC 3339 UTC timestamp.
2. Your webhook responds (within 5 seconds)
Connect the call:

200
Bridge the caller to target_number
{
  "action": "connect",
  "target_number": "9538822290"
}
Optionally override the number shown to the callee:

200
Connect with a custom caller ID
{
  "action": "connect",
  "target_number": "9538822290",
  "caller_id": "9484956709"
}
…or decline the call:

200
Reject the call
{
  "action": "reject",
  "reject_reason": "Number not available"
}
Response fields
Name	Type	Required	Description
action	string	No	"connect" or "reject". If omitted but target_number is present, connect is assumed.
target_number	string	No	Required for connect. 10 digits (with or without +91 / 91 — we normalize).
caller_id	string	No	Optional. Overrides the masked number shown to the person being called.
reject_reason	string	No	Optional message for a reject.
3. Verify the signature (recommended)
Compute an HMAC-SHA256 of the raw request body using your signing secret and compare it to the X-Edesy-Signature header.

// Node.js — verify the request came from Edesy
const crypto = require("crypto");
const expected =
  "sha256=" + crypto.createHmac("sha256", YOUR_SECRET).update(rawBody).digest("hex");
if (expected !== req.headers["x-edesy-signature"]) {
  return res.status(401).end();
}
Failure behavior: if your endpoint returns a non-2xx status, times out (>5s), or omits target_number, the call is rejected — unless you enabled “fall back to internal mappings” for the number, in which case it falls through to any internal pairing.
Error codes
Error responses use standard HTTP status codes plus an application code in the response body for programmatic handling.

All error responses follow this shape:

{
  "error": {
    "code": "insufficient_balance",
    "message": "Insufficient balance. Please add funds to continue making calls."
  }
}
HTTP	Code	Meaning	What to do
401	unauthorized	Missing or invalid API key.	Verify the Authorization header. Re-create the key if needed.
400	invalid_request	Request body could not be parsed.	Check JSON syntax and Content-Type header.
400	validation_error	A required field is missing or malformed.	Read the error message; fix the offending field.
400	invalid_numbers	Party A and Party B are the same number.	Use two different 10-digit Indian mobile numbers.
402	insufficient_balance	Wallet balance too low to start the call.	Top up your wallet, then retry.
404	not_found	The call_sid does not exist for your tenant.	Double-check the call_sid; calls older than retention may be purged.
500	internal_error	Server-side error.	Retry after a few seconds. If persistent, contact support.
Complete example
A runnable script that initiates a call, polls until it ends, then fetches the recording URL. Copy, paste in your editor, replace the API key, and run.

Node.js
Python
PHP
Copy
// Node.js 18+ — uses built-in fetch
const API_KEY = "vp_YOUR_API_KEY";
const BASE = "https://voice-api.edesy.in/v1";

async function call(path, init = {}) {
  const res = await fetch(BASE + path, {
    ...init,
    headers: {
      Authorization: `Bearer ${API_KEY}`,
      "Content-Type": "application/json",
      ...(init.headers || {}),
    },
  });
  const json = await res.json();
  if (!res.ok) throw new Error(json?.error?.message || res.statusText);
  return json.data;
}

// 1. Dial
const { call_sid } = await call("/masking/calls", {
  method: "POST",
  body: JSON.stringify({ party_a: "9876543210", party_b: "9123456789" }),
});
console.log("Call initiated:", call_sid);

// 2. Poll status every 2 seconds until terminal
const terminal = new Set(["completed", "failed", "no-answer"]);
let status;
while (true) {
  const log = await call(`/masking/calls/${call_sid}`);
  status = log.status;
  console.log("Status:", status);
  if (terminal.has(status)) break;
  await new Promise((r) => setTimeout(r, 2000));
}

// 3. Fetch the recording (if any)
if (status === "completed") {
  try {
    const rec = await call(`/masking/calls/${call_sid}/recording`);
    console.log("Recording URL (valid 24h):", rec.url);
  } catch (e) {
    console.log("No recording:", e.message);
  }
}
